# 引导型 AI 陪伴：开发进展与试运行说明

## 当前状态

架构 B 的工程闭环已经完成：`dsh-im` 负责可信私聊路由与渠道投递，`dsh-companion` 独立负责人格、关系、主动联系、联网话题、表情包和长期记忆。

- 微信和 QQ 都只接受精确配置的所有者私聊。首次合法入站建立可信主动路由，群聊、非所有者和通配符配置不会获得主动发送能力。
- 按用户时区持久生成 Morning、Topic、Evening 候选；进程重启、夏令时和跨日后仍保持每窗口至多一个候选。
- 支持 `gentle`、`natural`、`clingy` 三种模式。回复越稳定，互动可以更亲近；连续不回复会按 24/48/72 小时逐级安静。
- clingy 模式可在合适时追发一次，但用户回复会立即取消，附近已有正常候选时也不会叠加。
- 普通聊天和主动消息共用“自然、简短、引导倾诉”的人格边界，不允许威胁、自伤暗示、贬低、排他或道德绑架。
- 聊天内容可自动提炼为有证据、可过期、可遗忘的画像记忆；暂停记忆后不再提炼。原始入站文本不会直接复制进 companion 数据库。
- 联网发现只接收 `normal` 级别的抽象画像，查询会再次保守改写；只保留 HTTPS 来源，并进行评分、去重和遗忘联动。
- 本地表情包支持标签选择、渠道能力检查、路径穿越与符号链接防护、10 MB 限制和冷却。素材缺失时文字照常发送。
- 逐气泡幂等投递；结果未知时不盲目重试，明确 429 只允许在候选有效期内安全延后一次。

## 启动常驻调度

在插件配置中开启 worker：

```json
{
  "worker": { "enabled": true, "intervalMs": 60000 },
  "systemPrompt": { "enabled": true }
}
```

同一 Host 中运行 `dsh-im` 时，会自动向 companion 提供专用 Harness 会话，用于自然话术、记忆提炼和联网搜索。也可以在 companion 配置中显式选择 OpenAI 兼容接口；API 密钥通过 `apiKeyEnv` 指向环境变量。

真实试运行前还需要：

1. 在微信或 QQ 渠道填入自己的精确 owner ID，禁止用 `*`。
2. 开启 worker，并确认专用 Harness 或 OpenAI 兼容生成器可用。
3. 如需表情包，准备自有素材目录及 `stickers.json`；示例见包内 `stickers.example.json`。
4. 先用 `natural` 模式运行七天，再按真实回复习惯校准每日预算、安静时段和追发等待时间。

## 数据位置与控制

默认数据库：

```text
%DSH_HOME%/integrations/dsh-companion/companion.sqlite3
```

未设置 `DSH_HOME` 时，使用用户目录下的 `.dsh/integrations/dsh-companion/companion.sqlite3`。

```text
dsh-companion profile show OWNER
dsh-companion proactive status OWNER
dsh-companion proactive pause OWNER
dsh-companion proactive resume OWNER
dsh-companion memory list OWNER
dsh-companion memory export OWNER
dsh-companion memory pause OWNER
dsh-companion memory resume OWNER
dsh-companion memory forget OWNER MEMORY_ID --yes
dsh-companion memory erase OWNER MEMORY_ID --yes
dsh-companion memory clear OWNER --yes
```

删除只作用于 companion 本地数据库，不能撤回已经发到微信或 QQ 的内容，也不会静默删除 Harness Session、外部模型/搜索提供商数据或已有备份。
